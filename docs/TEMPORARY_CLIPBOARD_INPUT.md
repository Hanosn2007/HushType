# Text input methods

Dictation persists the processed text in recognition history before calling
`TextInserter.insert`. Text polishing uses the same inserter and retains its
result card. General settings retain a choice between temporary clipboard and
Unicode keyboard input in both Preview and stable builds. Clipboard remains the
default method, preserving the accepted behavior; the Unicode defaults are 100
UTF-16 units per batch and 1 ms between batches. The inserter dispatches events;
it does not acknowledge delivery
on behalf of the destination app or retry ambiguous input.

## Temporary clipboard behavior

1. Check event-posting permission before changing the clipboard.
2. Capture every available item and data representation. If capture is incomplete
   or clipboard ownership changes during capture, stop without replacing it.
3. Write the text and a unique ownership token. By default also write
   `org.nspasteboard.TransientType` and `org.nspasteboard.AutoGeneratedType`.
4. Dispatch Command-V without switching input sources. Await the configured
   grace period (default 500 ms) without
   blocking the main actor, then restore the original items only if both the
   clipboard change count and ownership token still match.

A newer clipboard write or clear takes precedence. Dispatch failure also restores
the snapshot when still owned. Once dispatched, task cancellation does not shorten
the waiting period. Overlapping calls are rejected until the transaction finishes.

The 500 ms grace period comes from the tested standalone demo; it is not a target
application completion signal. Clipboard ownership checks are best effort, not an
atomic lock against other processes. Markers are a convention respected by some
clipboard history tools, not a command to delete already recorded history. The
capture is in memory and never logged or persisted by the inserter.

## Preview control

Preview Settings → Debug → Temporary clipboard exposes the marker toggle.
`hushtype.input.temporaryClipboardMarkers` is a Boolean in UserDefaults, defaulting
to true when absent. Each insertion reads it anew. Turning it off removes the two
history markers but preserves the transaction token and restoration behavior.
Stable builds retain the input behavior and default; the debug page stays hidden.
Labels and error messages use the existing three-language localization resources.

The Preview page places input method, Unicode batch size and interval,
clipboard restoration delay, and markers in collapsed feature groups. Opening a
group retains its existing native controls. `TextInsertionConfiguration` is
shared by UI and runtime and can also be passed to `TextInserter.insert`. Its
preference keys and supported values are defined in that file. Each insertion
captures one configuration snapshot; changing parameters mid-input affects the
next insertion. Invalid stored values fall back to safe defaults.

## Unicode keyboard input

Unicode input never reads or changes the clipboard and never changes the input
source. Text is split at extended grapheme boundaries so surrogate pairs and
joined emoji are not split across batches. A single grapheme larger than the
requested batch size stays intact. Before each batch the original focused AX
element is checked when available; otherwise the foreground application is
checked. Losing focus or cancellation stops further batches. Partial delivery
never triggers automatic clipboard fallback.

The configured interval is a scheduling delay, not a throughput guarantee or a
destination acknowledgment. Zero yields to the main actor between batches. Other
values suspend without blocking the UI. The last batch has no extra delay.
The standalone demo's 100-unit / 1-ms configuration was manually accepted on
5000-character text; the integrated app still requires manual acceptance.

Stable builds hide the Debug navigation entry only. They keep the page declaration,
configuration types, preference reading, and both input implementations.

## Verification

`TextInserterTests` uses isolated named pasteboards and injected event dispatch;
it never pastes into a user's application. It covers multi-item/multi-format and
empty restoration, new-copy protection, permission and dispatch failure,
preferences, overlapping calls, and cancellation after dispatch. Actual app
compatibility, clipboard-history behavior, and the debug control remain manual
acceptance checks for the integrated build.
`UnicodeTextInputTests` covers configurable batching, Unicode integrity,
5000-character delivery order, clipboard non-interference, focus loss, and
failed/cancelled delivery without fallback.
